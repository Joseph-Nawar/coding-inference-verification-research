# 07 — Implementation and phase acceptance

## P0 — preflight only
Inventory macOS/Apple Silicon/RAM/free disk/Docker VM and limits, Python, MLX support; inspect model card, pinned revision, tokenizer, quantization and license. Verify exact EvalPlus release and official evaluation code, dataset sizes, special oracles, input schema, test provenance/license. Audit nearest papers and repo source versions. Establish split rule without opening final-task detailed tests for analysis; if library loads whole dataset in memory to compute IDs, document mechanical access, isolate loader and discard final payload, never expose to generation or researcher analysis. Review data licensing/redistribution, no code execution from unverified downloads. Pin all sources/requirements, record checksums. Establish security architecture, caps and stop conditions. Report discrepancies for approval if changes affect scientific design; don't invent substitutes. No generation or candidate execution before P0 security and version preflight passes.

## P1 — bounded smoke
Implement stage CLI, split manifest, generation, code extraction, runner, trusted scoring, evidence construction, cost ledger, tests and artifact store. Run synthetic security fixtures before model output execution. Check parity vs official scorer on known correct/incorrect programs and special semantics in safe isolated environment, including both benchmarks. Verify candidate code never gets host credentials, hidden labels, project mounts or shell. Use 8 smoke tasks, 2 samples each maximum, and up to 8 total additional smoke selector/repair calls (24 total). Validate prompt construction and deterministic extraction, one replay of cached output and a limited live seed replay (counts toward cap); report actual replay reproducibility rather than asserting. Include at least one deliberate invalid candidate fixture, separate from empirical results. Run V/D/H only on smoke; never final task predictions. Verify stage locks, input/output IDs, log/seed/version records, resource caps, and no H leakage to models. Report per-task results, feasibility not scientific significance. If model shows near-total failure/ceiling, report competence uncertainty and recommend different dev setup; not a program NO-GO. Use prelocked smoke sample; do not keep sampling until success. Stop P1 on safety/parity/provenance blocker or cap. No E1 unless researcher approves.

## Resource budgets (initial proposals; measured on actual machine)
See YAML. P0/P1 total model/data/image downloads <= 12 GiB, local new files <= 20 GiB, retain >= 15 GiB free disk, avoid memory pressure/swap escalation; no cloud/API cost. P1 max 24 calls, 18,432 output tokens, 90 min wall inclusive smoke run, plus separate P0 install/download <= 2h; stop safely and report if cap exceeded. No simultaneous model families, single inference stream and one runner worker. E1 max 320 calls, 245,760 output tokens, 8h wall. E2 max 96 calls, 12,288 output tokens, 3h. E3 max 112 calls, 86,016 output tokens, 5h. E4 max 24 calls, 12,288 output tokens, 3h. These caps are proposed stop limits, NOT runtime estimates or authorization. Before each E phase use P1 measured token throughput, prefill, execution overhead, RAM/disk and estimated time to propose a realistic revised cap and obtain approval. Run in resumable chunks (e.g. 5 tasks) with append-only ledger, do not restart completed samples. If resources prevent complete balanced sample, stop and report partial population; do not selectively fill positive tasks. Resource measures may be unavailable on some backends; explicitly report. No hidden work promised.

## Suggested layout (adapt only with rationale)
`src/coding_research/` (data, prompts, generation, parser, runner, evaluator, selection, analysis, CLI); `sandbox/` pinned trusted runner/build and security fixtures; `tests/`; `configs/`; `docs/`; `reports/`; `runs/<run_id>/` manifests, immutable outputs and results; `.research-private/` data/cache/checkpoints/evaluator-only labels and final split commitments. Gitignore local environments, weights, data, raw outputs and logs; do not publish by default. Local commits only. Use standard Python, typed JSONL, no arbitrary pickle loads from untrusted outputs. Provide repeatable stage CLI with --dry-run, --resume, --stage, explicit authorization token/manifest, validated config, atomic writes. Final-stage access denied by default, not just documentation. No fake passed evidence.

## Evidence schema (minimum)
Task: dataset/version/id/split/prompt_hash/eligible_flags/input partition hashes. Candidate: task_id/model_revision/condition/sample index/seed/prompt_hash/raw_hash/extracted_hash/parse_status/input/output tokens/stop_reason/elapsed. Execution: candidate_id/input_id/panel/status/typed output or error/runtime/runner version; reference/comparator records separate; no hidden payload in model-visible records. Selector: task_id/pool ordered IDs/condition/evidence IDs/model/prompt hash/decision/status/tokens/time. Repair: parent ID/branch/evidence IDs/new candidate ID. Ledger: stage/run/config/source hashes, timestamps, resource usage, status, exclusions, error category, retries/replays and reason. Store private raw values and hashes separately. Manifest SHA256 every retained artifact; record actual commands, versions, logs, test outcomes.

## P0/P1 report acceptance
`reports/P0_PREFLIGHT.md`: verified environment, resources, versions/licensing, data/evaluator contract and discrepancies, threat model, literature matrix, approved changes, stage status. `reports/P1_SMOKE.md`: exact commands, fixture tests and official parity, isolation inspect evidence, task/call counts, extraction and scoring metrics, replay, runtime/memory/disk, no leakage evidence, observed limitations. `P0_P1_STATUS.json`: per-check statuses PASS/FAIL/BLOCKED/NOT_RUN, artifact hashes, call and token counts, test/final access counters, unresolved blockers, recommended E1 scope. Include failures and logs not just successes. No scientific claims from 8 tasks. STOP and return for researcher review even on success.
