# 04 — Untrusted-code execution (mandatory fail-closed)

Generated programs, generated assertions, parser inputs and model text are untrusted. No host `exec`, `eval`, import, shell, unrestricted subprocess, or network access for generated content. Do not give the model tools or a shell. Offline inference host; use Docker Desktop Linux VM or separately approved isolated VM for execution. Docker is defense in depth, not a formal sandbox guarantee. If containment cannot be validated, STOP. Never loosen restrictions as fallback. For deliberate hostile-code research use stronger isolated disposable VM and separate approval; this is benign synthesis research.

## Execution architecture
Trusted orchestrator (host) owns task manifests and labels. Trusted reference calculation (isolated, pinned upstream code, no candidate) produces expected outputs. Untrusted runner container gets only candidate code, task entry point and necessary input(s) through bounded stdin or copy to ephemeral container, never a project/home bind mount. It must not see expected outputs, reference code, hidden input suites beyond the currently executed inputs, keys, token files or evaluator manifests. Prefer fresh process per test; benchmark semantics may require a particular per-candidate sequence — verify and document, isolate each candidate from other candidates. Trusted comparator outside untrusted process consumes bounded, schema-validated typed data; fail closed on unexpected output, protocol corruption or execution status. Do not accept candidate-printed PASS strings. No pickle from untrusted process. A candidate could still spoof its own return channel; document residual adversarial scoring limitation, test benign and adversarial fixtures and do not claim security against all malicious submissions. Official evaluation/parity runs that use upstream in-process checking must themselves run in dedicated locked-down containers with no personal files or shared state; do not expose their expected-output logs or candidate-visible evaluator internals to model. Use only for scoring if integrity requirements pass; investigate discrepancies, do not silently reconcile. Keep H execution out of generation pipeline.

## Container profile
Pinned ARM64 Python base image digest, reproducible dependency lock; prepare trusted image with network only during approved build/download. Runtime `--network none --read-only --cap-drop ALL --security-opt no-new-privileges --user 65532:65532 --pids-limit 32 --memory 512m --memory-swap 512m --cpus 1` plus bounded writable tmpfs (64 MiB, nosuid,nodev,noexec where compatible), no privileges/devices/host PID/IPC/socket, default or stricter seccomp. No inherited secrets; minimal env. No host binds, shared named volumes or Docker socket. Pull/build outside runtime only. Enforce bounded stdout/stderr (64 KiB combined per invocation), input and response size, process watchdog and container removal by ID even when client times out. Do not use `--rm` alone as timeout enforcement; use unique run labels, kill/remove on every exit, check no orphan containers; no destructive global prune. Default timeout policy must reconcile official per-test reference-time policy with hard safety caps; log safety-cap exceptions as infrastructure/resource issues, not silently wrong answers. Stage cap 1 concurrent candidate worker initially; increase only after validation. Docker Desktop VM resource limit and host memory pressure monitored. Verify actual flags with inspect and tests; do not assume configuration is enforced.

## Required P1 fixtures (synthetic, no host secrets)
Known correct/incorrect solutions, legitimate edge cases, syntax errors, wrong entrypoint, exception, timeout, oversize stdout, file-write denied outside tmpfs, failed network/DNS, absent sentinel host file and absent Docker socket, no access to secret canary environment, non-root/capability profile, bounded memory/child-process behavior, cleanup after timeout/crash, result protocol spoof attempt, cross-candidate state reset, invalid serialization, evaluator labels absent from worker and generation payload. Run harmless bounded fixtures only, no actual credential access or attacks outside container. Verify official comparator parity for tolerances, alternate valid outputs, typed containers, exception/timeout and special cases. If parity cannot be supported with adequate isolation, report blocker; do not substitute naive comparator. Retain inspect output, logs and test cases, scrub local identifiers from public release if later authorized.
