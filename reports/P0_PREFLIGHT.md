## EvalPlus semantics and isolation requirements

- Full HumanEval+ v0.1.10 and MBPP+ v0.2.0 contain 164 and 378 unique IDs. On 48 smoke/development records the audit checked task ID, prompt, entry point, contract, canonical solution, base/plus positional input lists and numeric absolute tolerance. Upstream MBPP conversion reconstructs task-specific tuples, nested tuples, sets with an empty-mapping convention, complex numbers and tuple-valued mappings. Apply conversion before typed input deduplication. The source uses `prompt + canonical_solution` for references and accepts either full solutions or prompt-appended completions. Use a pinned dataset override path for the HumanEval archive since the loader selects its default constant when constructing the dataset URL. [HumanEval loader](https://github.com/evalplus/evalplus/blob/e5d0ed0bab96280b60b637ec7f15b5e4841b0cb2/evalplus/data/humaneval.py) · [MBPP loader](https://github.com/evalplus/evalplus/blob/e5d0ed0bab96280b60b637ec7f15b5e4841b0cb2/evalplus/data/mbpp.py)
- Official Y requires both base and plus to pass. Each runs in a separate process with a single function load and ordered calls, so fresh function state per input can change scoring. References deep-copy inputs and record per-call times. Candidate comparison starts with native equality. Float/float-sequence expected values can switch zero `atol` to `1e-6` for the rest of the invocation. Tolerant fallback requires identical outer types, equal list/tuple lengths, and NumPy `allclose` at `rtol=1e-7`. Exceptions fail individual tests. Fast mode aborts on a failed test. Detailed mode can return partial details. Default per-test limit is `max(1.0 s, 4 × reference time)`. The suite watchdog adds grace to the smaller of the sum of limits and the default 60 s task limit. The env override arrives as a string in this release and would need independent validation. Upstream's default runtime memory budget can exceed the project's 512 MiB container cap. Resource terminations need a distinct infrastructure status. Pin Python hash seed and record hash-sensitive replay rather than assuming determinism. [Configuration](https://github.com/evalplus/evalplus/blob/e5d0ed0bab96280b60b637ec7f15b5e4841b0cb2/evalplus/config.py) · [Checker](https://github.com/evalplus/evalplus/blob/e5d0ed0bab96280b60b637ec7f15b5e4841b0cb2/evalplus/eval/__init__.py)
- Special rules include the HumanEval polynomial residual and MBPP alternate rounded surface area, padded digit distance, reference-or-zero `sum_div`, and `are_equivalent`, which makes successful returns pass after the initial equality evaluation. Eight MBPP entry points compare as sets and three reduce expected outputs to non-None booleans with a special case for candidate bools. Some rules admit many valid outputs or provide no meaningful discrimination. Signature analyses must establish eligibility independently of Y. [Special-oracle definitions](https://github.com/evalplus/evalplus/blob/e5d0ed0bab96280b60b637ec7f15b5e4841b0cb2/evalplus/eval/_special_oracle.py)
- The stock CLI asserts coverage of all loaded tasks, computes reference outputs for all loaded tasks, supports a pickle cache, and can reuse old result JSON. A checked per-task wrapper would use pinned checks and fresh namespaces, preserving original order and duplicate occurrences for the official endpoint. D/H would use typed deduplication and preserve original case identities without redefining full-suite Y. Keep P/V/D/H field allowlists, separate run/scorer workspaces and test synthetic canary exclusion before any model access. The pass@k calculation uses the usual per-task combinatorial estimator with fixed labeled samples and `n >= k`. [Pinned CLI](https://github.com/evalplus/evalplus/blob/e5d0ed0bab96280b60b637ec7f15b5e4841b0cb2/evalplus/evaluate.py)
- The runner threat model covers untrusted programs, serialized results, subprocesses, network, memory, output and lab data. Host-side control must enforce one worker, default seccomp, a read-only root, a bounded tmpfs, no privileges or host mounts, a cleared environment and network disabled, and removal by container ID. Bounded typed IPC and one-case-at-a-time delivery reduce disclosure. Distinct scorer and model processes must enforce label and withheld-data isolation. Docker capability reporting alone leaves the required runtime and isolation tests unverified.
