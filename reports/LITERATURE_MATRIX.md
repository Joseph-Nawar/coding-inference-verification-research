# Literature matrix

25 November 2026. This is a focused exploratory review. Full text means the paper was available and its relevant methods or results were checked. Repository discovery and implementation reproduction have separate status. No baseline was run.

| Source and status | Method, evidence and compute | Reproduction and overlap |
| --- | --- | --- |
| Liu et al., EvalPlus, NeurIPS 2023, arXiv v3. Full text and evaluator source audited. [Paper](https://arxiv.org/html/2305.01210v3) | Augments benchmark inputs with LLM-assisted generation, mutation and input contracts. Reference implementations supply comparison outputs. The benchmark changes correctness labels without increasing the candidate pool. | P0 checked the v0.3.1 source and release datasets. P1 runtime parity is blocked. H1/H3 depend on the validity and discrimination of these labels. [Pinned evaluator](https://github.com/evalplus/evalplus/tree/e5d0ed0bab96280b60b637ec7f15b5e4841b0cb2) |
| Chen et al., CodeT, 2022 v2 / ICLR 2023. Full text and repository record. [Paper](https://arxiv.org/html/2207.10397v2) | Generates separate candidate and input–output test banks, then scores shared successful execution groups using candidate and test support. Evaluated on HumanEval/MBPP and competition problems. Generating tests adds calls and the cross-product adds executions. | E1 V-output clustering only shares an agreement motif. Exact comparison requires generated tests, original grouping/weighting/deduplication and matched budgets. Original Codex results are not a local reproduction target. [Repository](https://github.com/microsoft/CodeT) |
| Li et al., S*, Findings EMNLP 2025. Full text and author repository record. [Paper](https://aclanthology.org/2025.findings-emnlp.865.pdf) | Generates in parallel, repairs failed public tests with execution feedback, and selects pairwise. In ambiguous comparisons it synthesizes distinguishing inputs, executes candidates and asks the model to decide from the comparison evidence. Private tests score final correctness. Generation, repair, input synthesis and judging add distinct costs. | H1/H3 and E2 overlap with its evidence interpretation. E2 freezes candidates and uses fixed official D inputs with controlled evidence arms. Full S* needs the sequential loop, adaptive synthesis and pairwise schedule, including fallback calls. [Repository](https://github.com/NovaSky-AI/SkyThought) |
| Chen et al., Teaching Large Language Models to Self-Debug, 2023 v2 / ICLR 2024. Full text via arXiv. [Paper](https://arxiv.org/html/2304.05128) | Code explanation and iterative revision with execution-dependent feedback where available. Evaluates SQL, translation and Python. Execution, explanation and revision carry distinct costs, with prompting and stopping conditions dependent on task. | E3's one-step execution-guided branch is an adaptation. Compare one-step template and no-op before extending to sequential repairs. Original model and benchmark settings require separate qualification. H2/H4/H5. |
| Zhong et al., LDB, Findings ACL 2024. Full text. [Paper](https://aclanthology.org/2024.findings-acl.49.pdf) | Breaks runtime traces into basic blocks and asks the model to verify intermediate variables and revise. HumanEval, MBPP and TransCoder. Tracing and revising add both context and execution cost. | Closest comparator if localization becomes central. E3's observed-versus-expected return packet omits trace states. H2/H4. |
| Chen et al., Revisit Self-Debugging with Self-Generated Tests, ACL 2025. Full text. [Paper](https://aclanthology.org/2025.acl-long.881.pdf) | Separates post-execution input/output discrepancies from in-execution intermediate-state feedback. Across basic and competitive benchmarks, test-label errors can degrade post-execution repair and the size of the effect varies. Reports an initially correct program regressing after wrong feedback. | Direct overlap for H2/H3/H5. E4's fixed, benchmark-valid inputs isolate label errors from input validity. E3's preservation panel measures regressions with a predeclared V-based eligibility rule and retrospective Y strata. |
| Snell et al., Scaling LLM Test-Time Compute Optimally, arXiv 2408.03314 / ICLR 2025. Full text. [Paper](https://arxiv.org/html/2408.03314) | Allocates test-time compute with revision models and verifier-guided search across difficulty bins in math. Computes matched-budget comparisons within the reported model/verifier regime. | H6 motivation. Exact Python synthesis transfer is an empirical question. Report token and execution costs beyond matching calls. |
| Jain et al., LiveCodeBench, arXiv 2403.07974 / ICLR 2025. Full text sections on benchmark construction and licensing. [Paper](https://arxiv.org/html/2403.07974) | Time-stamped competition problems, code generation, repair, execution and output prediction. Public examples and separate scoring tests. Benchmark dates support contamination analysis. | Future external validation requires a release, date cut, platform/problem-content terms and new sandbox parity. Metadata-only review in P0. [Repository](https://github.com/LiveCodeBench/LiveCodeBench) |
| Kulkarni et al., Debug or Regenerate? Test-Guided Selection for LLM Code Repair, Findings EMNLP 2026. Full text. [Paper](https://aclanthology.org/2026.findings-emnlp.2173.pdf) | PATSSEL compares mixed debug/regenerate against two attempts of each single strategy under the same selection mechanism. Base-generated, RL-generated or gold routing tests on LeetCodeDataset, LiveCodeBench and HE+Fix. Initial quality predicts relative effectiveness. Their error analysis also identifies weak or non-discriminative tests. | Direct overlap with H1/H3/H4/H6. A context × feedback intervention and initially-correct preservation panel test distinct questions from routing among initially buggy programs. Training, trained checkpoints, routing artifacts and verifier token costs need resolution before reproduction. |
| He et al., Verification Trap, EMNLP 2026 / arXiv v1. Full text. [Paper](https://arxiv.org/html/2610.05170v1) | Compares original, irrelevant-control and false-premise prompts on three benchmarks and five coding models. Uses 64 sampled candidates per task-condition, generated verifier tests and hidden correctness for analysis. Studies mixed-correctness signatures and decoupled auditors. Appendix S8 gives inference stages and leaves exact wall time/token costs unreported. | Direct overlap with E1 oracle/selection gaps and E4 dependence. Planned clean prompts and fixed input panels can measure discrimination and validity. Shared causal premise dependence needs an explicit intervention and matched verifier comparison. Exact artifact/code pin not established. |
| Rakasi et al., When Uncertainty Isn’t Enough, ICML 2026 workshop preprint v1. Full text. [Paper](https://arxiv.org/html/2608.14659v1) | Compares five uncertainty signals on HumanEval and BigCodeBench across three small code models. Multi-sample confidence and execution-based correction consume additional inference. Some estimators require hidden states or fitted calibration. | H3/H5/H6 calibration and selective regeneration comparator. Comparing cheap and expensive signals requires actual token and execution accounting. Exact code pin not established. |
| He et al., HardTestGen, ICLR 2026. Conference paper available, abstract and method framing reviewed. [Paper](https://openreview.net/pdf?id=v3SzGCfAXN) | Synthesizes discriminative algorithmic coding tests using a pipeline with stronger reference evidence and evaluates verifier precision and downstream RL. Preprint dataset counts differ from proceedings, so use the proceedings for comparison. | H3/E4 overlap on discriminatory testing. Exact reproduction requires labeled reference and solution pools and large-scale synthesis/training beyond this handoff. |
| Ridnik et al., AlphaCodium, arXiv 2024. Paper and implementation overview checked. [Paper](https://arxiv.org/abs/2401.08500) | Multi-stage CodeContests workflow uses public and generated test anchors, then iterates on candidate code. Generation and execution budgets differ from one-shot prompting. | H2/H3. Test anchors motivate trustworthy evidence, while E3 holds the failure packet fixed across code-context arms. [Repository](https://github.com/Codium-ai/AlphaCodium) |
| Reassessing One-Round Test-Time Refinement for Code Generation and Understanding Regression in Code Self-Refinement, 2026. Full texts available, results and scope reviewed. [Refinement with and without execution](https://www.mdpi.com/2673-2688/7/9/353) · [Without execution feedback](https://www.mdpi.com/2673-2688/7/10/416) | Explicitly decompose repairs and regressions across local coding models and task sets. The latter withholds benchmark outcomes from refinement and compares controlled text-only protocols. | Direct overlap with H5. A new study needs more than a regression rate. Predeclared V-pass inclusion and a task-level context–evidence interaction are concrete distinctions to test. Exact code/data pins pending. |
| PAIR-Bench, arXiv 2607.01360. Full-text record available, abstract and scope reviewed. [Paper](https://arxiv.org/abs/2607.01360) | Measures progressive code improvement under adaptive interactive feedback and observes correctness across steps. | H2/H5 overlap on feedback trajectories. E3 is a single matched intervention. Review feedback components and cost before any trajectory comparison. |

Search topics covered discriminative tests and generated-label validity, evidence diversity and localization, initial-code anchoring and regeneration, regression, uncertainty/calibration, generator–verifier dependence and budget matching. The three tentative 2026 identifiers in the handoff resolve to PATSSEL, Verification Trap and When Uncertainty Isn't Enough. The overlap rules out treating debug/regenerate complementarity, nondiscriminative tests, or repair regressions as standalone novelty claims. Equal generation attempts, matched wall time, and matched token/runner budgets are distinct comparisons.

Repository HEADs observed in P0 are provenance checkpoints for the review. Full experiment reproduction still requires identifying the revisions and artifacts used by each paper.
